# Linux 早期接管诊断

日期：2026-11-12。第九轮用户确认八黄、五青、无红，随后明确手动重启回原厂 Android；没有同次二进制 journal，未证明 MMU 开启。本候选增加第九个受固定原厂哈希和逐指令校验约束的分支钩子，定位 MMU 后入口，最终目标仍为 iOS 14。

## 标记与指令

原有底部五块青色仍表示恢复检查点 06–10；它们上方新增独立黄色行，依次累计以下标记。

| 黄色块数 | 已到位置 | 原厂 Image 偏移 |
| --- | --- | --- |
| 1 | Linux 最早入口钩子 | `0x1000` |
| 2 | EL 初始化返回，准备计算物理偏移 | `0x1008` |
| 3 | 物理偏移计算返回，准备保存启动模式 | `0x100c` |
| 4 | 启动模式保存返回，准备读 MIDR | `0x1010` |
| 5 | CPU 表查找返回，尚未判断是否匹配 | `0x101c` |
| 6 | FDT 检查和早期页表建立返回 | `0x1030` |
| 7 | CPU setup 返回，进入原厂 enable_mmu | `0x180800` |
| 8 | TTBR 写入完成，准备执行原厂 SCTLR/ISB/BR 序列 | `0x180820` |
| 八黄后的第九格绿色 | 进入高虚拟地址入口的诊断钩子；仍在 BSS 清零前 | `0x1230` |

钩子无栈运行；被替换的指令在恢复 stub 中重放，跳转目标与 literal 都从已固定原厂 Image 核验。所有其他原厂主体字节保留。最后三条开启 MMU 的原始指令连续执行，中间不插入服务调用或字面量访问。八块黄色仍不能证明 MMU 开启成功。第十轮候选另为 stub 所在物理 2 MiB 块增加短期可执行恒等映射；否则移到 stub 内的 SCTLR 指令会在开启转换时使诊断代码本身失去映射。第九轮不能据此直接解释为原厂 Linux 缺陷。

开启 MMU 后的显示还依赖 `0x42402000` 的临时 L2 表，只映射显示所在四个 2 MiB 块，使用 Device、AF、不可执行属性。记录指针改用 Linux 高虚拟地址访问；该表位于既有 Image 预留窗及 BSS 内，在原厂 BSS 清零时被清除。绿色仅证明进入该早期钩子，不能证明 BSS 清零、start_kernel 或 Android 启动。

在进入 Linux 前，另外安装 2 KiB 对齐的短期异常向量。Linux 正常写入自己的 VBAR 时结束该向量的覆盖范围；它不能保证抓到那之后的 MMU 故障。异常发生时保留 ESR/ELR/FAR，并在左侧绘制三行十六进制数（由上至下依次是这三项），新增第九格红块后停止，不伪造恢复成功。

FDT 8 KiB 预留属性的尾部：4712 为最后检查点（u32；1–8 黄、9 绿），4716 为异常向量序号（u32），4720/4728/4736 为 ESR/ELR/FAR（u64），4744 为异常绘制完成（u32），4752/4760 为 MMU 后的 SCTLR_EL1 和钩子 PC（u64）。异常使用绘图编号 10，仍位于第九格。写入使用 32 位访问。原来 512–4607 的 journal 和 4608 起同次入口状态不被覆盖。

## 验证范围

普通、严格对齐和损坏 EFI 三个 QEMU 场景保持在 Linux 入口前停止。另有 `--linux-early` 使用明确哈希的额外 ramdisk 副本，执行真实原厂 Linux head、CPU 表查找及虚拟 CPU setup，至第八个黄色检查点停止；不执行后续 MMU 跳转，也不模拟 Kryo 或完整 Qualcomm Linux。Linux 自行修改启动全局变量后，不要求内存镜像继续与静态输入相等；完整 CPU 源/目标读回比较在进入 Linux 之前执行并单独检查。

`--linux-early-trap` 仅在 QEMU 临时副本将 Image+0x1010 改成未定义指令，要求正确记录检查点 3、同步向量 5、ELR=0x40081010，完成 ESR/ELR/FAR 绘制并检查 framebuffer 像素。这个故障注入不进入真机镜像。

`--linux-post-mmu` 使用同一额外 ramdisk，仅在 QEMU 临时 shim 副本开启 MMU gate；偏移从 ELF 符号计算，实际加载副本另记 SHA-256。要求真实 SCTLR.M=1、PC 匹配高虚拟地址钩子、检查点 9、无异常，并检查全部八黄及第九格绿色像素，然后在 BSS 清零前停止。QEMU 的停止分支不进入硬件版本。

真机脚本要求以上六项报告与当前 QEMU FD/镜像相符，再校验硬件/模拟源文件相同及本地镜像哈希。报告分别在 `uefi-qemu*.json`；真机实验结果仍以 `uefi-device-attempt-XX.json` 为准。第九轮固定输入与原五项验证存于 `reports/local/20261112-221620-668581-uefi/inputs/`；旧汇总另存 `uefi-linux-early-attempt-09.json`，不把新候选验证写成第九轮真机结果。
