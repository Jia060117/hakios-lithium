# iOS14与上游16.5集成核对

2026-11-16。活动内核保持完整HakiOS63fc2b4/XNU8796.121.2；本次Windows端查询上游HEAD/main均仍为该提交，未更换基线。原始checkout保持干净，正常依赖和设备/配置/驱动清单检查通过。

输入来自原18H17/d20ap根卷及用户提供的20F66/d22ap IPSW。16.5 OS与SystemOS Cryptex已从IPSW只读提取，校验ZIP CRC、长度及SHA256并只读挂载。对比7个原始程序的Mach-O版本、导入和哈希，2项原始服务plist、共享缓存布局，并核对14.8原始launchd反汇编、间接符号绑定和实际映射字符串。没有把16.5程序复制到14.8运行系统。

| 边界 | 真实输入与上游证据 | 处理 |
| --- | --- | --- |
| 共享缓存位置 | 14.8根内单文件2,218,328,064字节；16.5缓存来自独立SystemOS Cryptex并拆分多个文件 | 保留18H17原始缓存与原根路径；上游16.5选择器不可原封套用 |
| 原始服务配置 | cfprefsd的两个plist SHA256完全相同；notifyd的16.5配置多LimitLoadToSessionType，14.8无此键；两者服务端口名称对应 | 使用原14.8 plist，由完整上游mkjobs生成两项服务；RunAtLoad仅用于本次有界进程检查 |
| Data目录和时区 | 已有原14.8卷元数据；上游mkvarskel的16.5时区默认会与14.8原链接形成环 | 继续使用原14.8目录元数据及已存在的环路修正；上游ramfs初始化，本次不改变持久Data布局 |
| PID1标准描述符 | 原14.8 launchd的0x1000107a0调用isatty(1)，拒绝分支exit78；目标XNU mmioctl未知/dev/null请求返回ENODEV19 | 修正诊断ENOTTY-only断言，验证非终端；记录open/dup0/dup1/close/tty结果，保持原程序与内核策略 |
| UFS根切换后的rd | 原14.8地址0x10004c983实际字符串是rd=md0；相关分支0x10003751c至0x100037574。上游FLASHBOOT注释明确在磁盘根切换后保留此参数 | 保留上游合同，系统根在UFS按需读取；不因此把整镜像载入RAM。分支运行及后续启动任务仍待真机 |
| dyld接口 | 已有原14.8 shared_region438兼容及R24动态程序运行证据 | 保留范围明确的HakiOS接口兼容，无法靠文件布局替代 |
| Mach消息 | 已有精确SDK14.8旧Mach消息入口兼容；R24原df/mount均exit0 | 保留原校验与权限路径，不扩大到任意版本 |
| 私有服务、IOKit及A530图形 | 导入列表与文件存在只能确定输入，不能证明全部ABI或硬件行为 | 后续按实际缺失接口核对上游集成；本轮不声称完整兼容或图形已成立 |

镜像/部署配置能够补齐已确认的文件、路径、元数据和启动配置差异。但既有shared_region与Mach消息差异已经需要HakiOS中的有界内核兼容，故目前不能把完整跨版本支持承诺为仅修改镜像。此次检查未发现需要为了R26错误更换HFSX、UFS分区或全量加载RAM的证据。

R27只落实当前可明确修复的交接检查及日志，并核验与上游的集成。已有上游公共服务、libmini、init/rc、生成器及原始14.8程序继续使用；cfprefsd/notifyd配置没有为模仿16.5而增加无证据的改动。原R25 abort仍待新的真机证据；进程存在也不等于全部服务API通过。
