# HakiOS 系统镜像路线核对

2026-11-16。以固定完整 HakiOS 63fc2b4 / XNU8796.121.2、18H17/d20ap 和 R26 原图为依据。用户已明确：系统存放 UFS 并按需读取，继续使用已经通过的存储链路。

上游 `select-system.py` 筛选资源，`userland/build.sh` 使用 `mkapfs.py -z` 文件级压缩；上游源码所述约5.4GB文件生成2.5GB镜像来自两者共同作用。上游同时支持 FLASHBOOT 磁盘根卷。镜像体积和 RAM/UFS 启动介质是独立选择。

现有根卷是从18H17系统文件构建的未压缩HFSX：逻辑容量16GiB，普通文件8,651,900,353字节。它不是整个IPSW原封写入。手机仅写过一个userdata物理分区；`/private/var`、`/private/preboot`等属于挂载路径，不能据此判断有多个iOS物理分区。

只读选择估算：原238674个普通文件；原封16.5选择器保留36586个/2,197,153,372字节，但会删除iOS14根内的dyld共享缓存。显式保留该缓存后为36587个/4,415,481,436字节。这仅是选择估算：尚未核验完整依赖闭包、构建候选压缩镜像或测试其启动，不能承诺小于3GB。16.5独立Cryptex布局不能直接套给14.8。

R26原图确认UFS/HFSX只读根切换成功、原始launchd匹配、ramfs初始化2检查/0失败、rd=md0；随后stage6/errno19，120766ms后正常返回，无panic。新增描述符检查误要求/dev/null终端查询返回ENOTTY25；目标XNU mmioctl未知请求实际返回ENODEV19，与停点吻合。照片未分别记录open/dup/ioctl子步骤；R25原始launchd的abort原因仍未解决。

下一步修正目标描述符语义和测试契约、保留各步骤结果，核对完整上游init/rc/FLASHBOOT及18H17原始程序需求，再准备针对性launchd复测包。系统保持UFS按需读取，精简压缩不作为修复前置条件；本次无证据要求改分区或文件系统。512MiB内核内存窗口不限制UFS镜像容量。

完整只读输入、源码哈希和估算见 [JSON](hakios-system-image-route-audit.json)。P1、R20存储及R24动态工具已通过，本次不重复其完整验收。原7195路线保持只读冻结。
