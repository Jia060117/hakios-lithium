## 2. 公共前置和活动实现现状

- 外围 boot-args parser 在 `ports/hakios-lithium/peripherals/boot-options.h:41-50,56-104`；外围 worker 在 `ports/hakios-lithium/peripherals/kernel.inc:18-56`。选项默认值为关闭。`touch=`、`touch_log=`、`touch_poll=`、`gpu_probe=`、`gpu_stage=0..4`、`gpu_wd=` 是**受保护的请求/诊断选项**，不是已接线驱动开关。
- 现行 admission hook 在请求触摸/GPU 时明确写出 `platform_backend_unverified` / `power_smmu_scm_backend_unverified`，并报告 `mmio=0`、`irq_attached=0`、`hid_events=0`（`kernel.inc:30-35`）。没有触摸/GPU MMIO；这保证未知硬件状态下 fail-closed。LITHIUM 日志走既有 `printf` / 控制台捕获路径；USB 全程和全量日志仍需设备侧验收。
- 活动 HakiOS lithium 内核没有已核实的 TLMM GPIO、MSM8996 QUP 实际传输后端、PM8994 SPMI/RPM 电源 handoff 后端。QUP/touch 文件是 host-tested 协议或回调候选，不是可运行的板级驱动。
- 上游 HakiOS GICv3 在 `upstream/hakios-xnu-kernel/xnu/files/osfmk/arm64/gic_v3_irq.c:225-266,482-488` 根据当前 MPIDR 写 SPI 的 `GICD_IROUTER` 并申请 ARE_NS affinity routing；没有相应读回与本机 GPIO/GPU IRQ 实际投递证明。R15 保存日志确认 `bootcpu=1 cpus=1` 时 `logical=0 mpidr=0x80000001 affinity=0x1 max_logical=0 match=1`（`reports/hakios-ios16-device-r15.md:10,16`）。此证据确认 R15 的启动核，不确认每条 SPI 都已路由/收到。
- 本次触摸坐标 helper 在 `touch-queue.h:34-66`；digitizer adapter 通过同一函数转换（`touch-digitizer.h:38-65`）。逻辑 framebuffer 尺寸、旋转、面板映射和真实传感器校准仍需要真机证据。BGR24 的 `stride=3240` 对应 1080 像素/行；不能把每像素误当 4 字节算成 810。

## 3. A1 触摸调查

根据保存的 lithium DTS 与 Android inventory（均为存量主机资料，不是当前手机查询）：

- DTS 的 QUP/I²C12 位于 `artifacts/stock/V9.5.2.0.NAHCNFA/lithium-stock.dts:4844-4861`，基址 `0x075ba000`、输入时钟 19.2 MHz、配置速率 400 kHz，active pinctrl 使用 GPIO87/88。节点 `:4863-4883` 为 `ft,ft5x46_i2c@38`；保存 inventory `reports/local/20261112-142718-199681/inventory.json:190-192` 记录 `12-0038`。它支持 FT5x46/FTE8716 家族判断，但没有当前运行芯片 ID/固件版本读数。
- **IRQ 数据冲突未解决：**通用 `interrupts` 属性指向 GPIO105（DTS `:4866-4867`）；`irq-gpio` 和 active pinctrl 指向 GPIO125（`:4881-4883`）。现有 audit 把 GPIO125→TLMM SPI208→GIC INTID240 作为候选映射，并记录 Android 下游使用命名 GPIO/下降沿；不能将此映射写成实机验证。GPIO89 是 reset 候选。Android 保存的 reset 等待时序只是驱动流程证据。
- 电源引用 PM8994 L14，1.8 V；LAB/IBB 与显示共享（DTS `:4868-4873,6315-6335`）。没有 UEFI→XNU rail owner/handoff 实测；不得通过盲目切换共享 display rail 来“探测触摸”。
- 存量 Android driver 审计记载 63 字节报告、3 字节 header + 10×6 contact、12-bit X/Y、4-bit id、`0xf` terminator，以及 `0x00/32` 与 `0x20/31` 分两次读取。缺少原始按下/移动/抬起帧；split-read 是否锁存同一帧、格式和固件版本都未验证。
- HakiOS 有 `/dev/hakios-touch` 和 backboardd virtual HID injector；没有实体 digitizer producer。`upstream/hakios-xnu-kernel/xnu/files/bsd/sys/hakios.input.h:2-11,18-43` 与 `userland/src/inject.c:748-849` 描述的是虚拟输入路径。Host test 生成事件字段不等于 Apple IOHIDFamily 收到物理触摸。

实现阶段仍缺：GPIO/TLMM 与 I²C12 pin/clock/reset ownership、有限且可中断的总线读写、硬件触摸 init/IRQ/轮询、物理报告进入 HakiOS queue 的生产接口、backboardd/IOHID 端到端消费确认。现阶段不能指导运行 `touch=1` 或 `touch_poll=1` 来验收实际触摸；只会命中 fail-closed admission 日志。

## 4. B1 GPU/Metal 调查

参考源码固定版本/commit 与精确行号详见 `gpu-reference-verification.md` 和 `gpu-upstream-components.md`：UniXNU `c34f018aafd6befd5dc93c05a8dccd5bdce6724b`，其 A740/AdrenoMetal 子模块也按报告 pin；HakiOS kernel `63fc2b4633bac3af8e57dadab9f5a8d4cb940438`；HakiOS userland 旧仓库入口 `2573c4a8d80ed143e534d16b5a386efa5b06ccbb`（仓库说明已并回主仓）；Dada `f1ae906fcc43ba8f763663257724ba938fb820ab`；dipper-xnu `2854c1e22fc2d73bb7a890c2c84b80182ea5ad18`；Linux v6.12 `adc218676eef25575469234709c2d87185ca223a`；Mesa 25.0.7 `742a20f48c59e8649533c84c4d49dd95b403f5da`。网络可用；缺失参考以临时浅克隆、无 checkout 方式核对，未纳入启动包。

- 源码显示的候选链路是 Metal frontend/object → NativeMetal bridge → Vulkan/Turnip → NativeAdreno kernel ABI。NativeAdreno API 含 BO/import/map、submit、fence 等；被检查的真实 GPU engine 是 A740/SM8550，不是 A530。Dada 的 gpu2 来源面向 A830/arm64e/iOS26，不能直接作为 MIX/iOS16 arm64 驱动。
- pinned Mesa 25.0.7 中 GPUId 530 属于 A5XX；`src/freedreno/vulkan/tu_device.cc:1405-1407,1452-1455` 对此 pin 的 Turnip Vulkan path 只接纳 gen6/gen7，默认分支拒绝其他 generation；Gallium `freedreno_screen.c:1046-1048` 有独立 gen5 `fd5_screen_init` 路径，这不代表 A530 Turnip/Vulkan 已支持。结论只限定上述 pinned revision，不外推所有版本/fork。
- `gl=0 metal=0` 维持软件 CoreAnimation 绘制候选；单独 `gl=1` 的 OSMesa 也可能仍是软件渲染。打开 Metal/插件名不能补出 A5xx GPU backend。
- MIX 的 GPU 电源/GDSC、GPU/AHB/RBBM clocks、regulator/CPR、SMMUv2 context/SID/TLB、DMA/cache coherency、SPI/IRQ、reset/quiescence 均未运行验证。存量资料含 PM4/PFP/GPMU、ZAP/PAS13 相关来源和固件名，但当前设备固件/版本、TrustZone/SCM 从此 UEFI/XNU 环境能否安全加载都未验证。没有证据支持“CP 非安全模式可替代”。未上电块的 MMIO 可能直接挂总线，software timeout 不能抢救一条阻塞 MMIO。
- 新增 fence packet、GPU ring、watchdog/recovery 测试操作的是 CPU 内存数组和合成 acknowledgements；不提交到 Adreno，不建真实 GPU 页表，不等待真实中断，不验证软件显示回退。Stage 0/1 必须继续保持无真实 MMIO，直到安全电源/时钟/SCM/SMMU ownership 和 reset 先决条件被证明。
