## Material findings

### F1 — P1: production admission is not the requested driver integration

`ports/hakios-lithium/peripherals/kernel.inc:1-5` explicitly describes an admission point without MMIO and includes only the option parser. The worker checks observed affinity 0x1 and maximum logical CPU 0 (`:20-28`); with the expected CPU contract, a touch request produces `platform_backend_unverified`, `mmio=0 irq_attached=0 hid_events=0` (`:29-32`), and a GPU request produces `power_smmu_scm_backend_unverified`, `mmio=0 software_fallback=1` (`:33-36`). There is no call to the QUP candidate, touch adapter, GPU probe model or GPU submit mock in this hook.

Initialization parses bounded boot arguments, rejects malformed input, remains quiet when neither feature is requested, and schedules one callback on allocation success (`ports/hakios-lithium/peripherals/kernel.inc:40-58`). This is useful refusal/admission behavior. `touch=1`, `gpu_probe=1` or a requested GPU stage cannot turn it into hardware functionality. The contract explicitly says both drivers are unimplemented (`ports/hakios-lithium/peripherals/contract.json:13-14`).

The hook's claimed call site is documented in its comment, but the active kernel caller, final link and packaged binary were not independently checked here. The contract's before/after input-source hashes (`ports/hakios-lithium/peripherals/contract.json:3-8`) are declarations, not this review's proof of a built or running integration.

### F2 — P1: the QUP candidate cannot currently satisfy the touch transport contract

This is a concrete interface gap, beyond missing hardware qualification. `maintenance/hakios-lithium/peripherals/touch-i2c.h:40-44` requires START + address/write + register byte + repeated START + address/read + STOP. Its report helper requests the stock-style split reads 0x00/32 bytes and 0x20/31 bytes (`:155-170`). However, `maintenance/hakios-lithium/peripherals/qup-transfer.h:16-18` explicitly limits its candidate to one nonempty message of at most 32 bytes and excludes repeated START and device-register addressing. Its packer encodes a single read or write message (`:121-143`), and its transfer API accepts no register/combined-message descriptor (`:187-205`). Passing independent unit tests does not bridge these contracts. Two separate stopped transfers would not by themselves implement the required combined transaction.

The candidate contains real sequencing logic and finite wait/cleanup policies, but platform facts are caller attestations: mapping, QUP layout, power, clocks, pins, timing, exclusivity and bounded ordered callbacks (`maintenance/hakios-lithium/peripherals/qup-transfer.h:40-66,80-86`). It does not establish those facts on lithium. The fake fixture supplies all attestations, a synthetic clock value and RAM-backed registers (`maintenance/hakios-lithium/peripherals/qup-transfer-test.c:7-39,44-84,105-113`).

Physical A2 remains unproven: board resource handoff, a working combined I2C backend, runtime controller identity, physical IRQ/poll acquisition, real idle/down/move/up frames, delivery into the HakiOS input path and visible interaction. The scoped audit itself records missing lithium TLMM/BLSP implementation and unverified power (`reports/hakios-ios16-lithium-peripherals-audit.md:11-12,24-29`). Even serializing both split reads does not prove the controller latches one frame across them; the touch helper explicitly leaves that to hardware evidence (`maintenance/hakios-lithium/peripherals/touch-i2c.h:155-156`).

### F3 — P1: neither B2 hardware stage 0 nor stage 1 has been demonstrated

Stage 0 is a callback orchestration model. Its resource order explicitly does not encode a board power sequence (`maintenance/hakios-lithium/peripherals/gpu-probe.h:11-16`). Verified identities/ownership are caller-provided booleans (`:37-44,70-79`); actual preparation, ID access and cleanup are delegated callbacks (`:46-59,89-118`). The fixture advances an integer clock and returns a stored chip ID (`maintenance/hakios-lithium/peripherals/gpu-probe-test.c:7-25,35-54,66-82`). A successful modeled comparison to 0x05030004 is not a physical RBBM read, validated power/clock sequence or secure-ownership result. The production hook does not invoke this model (F1).

Stage 1 is explicitly a mock. `maintenance/hakios-lithium/peripherals/gpu-submit.h:8-20,31-44` defines a CPU-array ring with synthetic observations and quiescence proofs. The five-word fence packet uses a fixed mock address with **no backing mapping** (`:94-111`); it must never be submitted to hardware as-is. Completion is determined from a fence value and IRQ boolean passed into `lithium_gpu_mock_sample` (`:123-141`). Quiescence similarly trusts two caller booleans (`:160-178`). These are state-machine inputs, not GPU DMA, an interrupt handler, a hardware watchdog or proof that DMA has stopped.

Missing B2 target evidence includes safe stage-0 register access; qualified rails/domains/clocks and secure-state ownership; an A530 firmware/CP initialization path; real SMMUv2/IOVA mappings and cache visibility; hardware ring submission and fence writeback; completion/timeout observation; and recovery that retains DMA-referenced pages until actual quiescence. These prerequisites are recorded as unverified in `reports/hakios-ios16-lithium-peripherals-audit.md:48-52`; this review did not inspect firmware or validate those reference sequences on the target. Higher Metal/presentation stages also remain outside acceptance (`reports/overnight-20261118/gpu-upstream-components.md:96-106`).

### F4 — P2: the touch queue helper is useful logic, not an end-to-end frame delivery path

The adapter validates/maps geometry, tracks identities/slots and builds ordered release/begin/move events (`maintenance/hakios-lithium/peripherals/touch-queue.h:26-56,64-95`). Its event/batch records contain no timestamp or explicit consumer frame-commit record (`:15-24`), stationary contacts are retained in state but omitted from output (`:87-92`), and the caller must deliver the entire batch in order. The header explicitly disclaims upstream queue atomicity and consumer acknowledgement (`:59-62`). State is committed before any external delivery can be acknowledged (`:94-95`). A future producer needs a defined loss/backpressure and full-hand/frame policy so partial delivery cannot leave stuck or inconsistent contacts. These are integration obligations, not a claim that the standalone helper violates its documented contract.

The fixture manufactures 63-byte frames and examines returned batches (`maintenance/hakios-lithium/peripherals/touch-queue-test.c:5-15,25-43`). It does not call `hakios_touch_post`, drive `/dev/hakios-touch`, exercise IOHID/backboardd or demonstrate physical input. The audited design calls for one monotonic timestamp per valid frame, stable contacts and explicit releases (`reports/hakios-ios16-lithium-peripherals-audit.md:31`); the complete implementation of that path is not present in the inspected admission hook.

## GPU reference claims and their limits

The corrected reports distinguish source plumbing from a transferable physical backend. The finding that the four MSM8996 component names lack verified implementation bodies is explicitly bounded to their audited trees (`reports/overnight-20261118/gpu-upstream-components.md:7-18`); this final review did not repeat those repository-wide negative searches or certify global absence. A740 NativeAdreno and NativeMetal are documented as real reference implementations, while Dada's newer pipeline targets A830/arm64e/iOS26 (`:31-60,75-92`). Those source-chain findings were read as attributed reference-audit findings, not independently reproduced target results.

One decisive compatibility claim **was independently rechecked against exact Git objects** in `artifacts/reference-source/overnight-20261118/mesa-25.0.7` at `742a20f48c59e8649533c84c4d49dd95b403f5da`:

- `src/freedreno/common/freedreno_devices.py:287-291` places GPUId(530) in CHIP.A5XX.
- `src/freedreno/vulkan/tu_device.cc:1405-1407,1452-1455` admits generations 6/7 in that switch and rejects the default generation with `VK_ERROR_INITIALIZATION_FAILED`. Thus this pinned Turnip path excludes A530/gen5.
- `src/gallium/drivers/freedreno/freedreno_screen.c:1046-1048` separately dispatches generation 5 to `fd5_screen_init`. A5xx Gallium support does not establish A5xx Turnip/Vulkan.

This corroborates `reports/overnight-20261118/gpu-reference-verification.md:24-42`. It does not establish an impossibility for every other version/fork. A transport shim, NativeAdreno ABI match or enabling Metal/M2V cannot by itself fill the missing gen5 Vulkan implementation. The download rejection/byte-comparison ledger (`:50-66`) was read as a prior audit result, not rerun; no firmware/download validation is claimed by this review.

## Panel units: confirmed, with geometry acceptance still separate

The known physical scanout is **BGR24, stride 3240 bytes: 3240 / 3 = 1080 pixels**, with height 2040. Dividing by four yields the erroneous 810-pixel interpretation. This agrees with `AGENTS.md:1`, `PLAN.md:1`, `OPERATIONS.md:3` and `reports/hakios-ios16-lithium-peripherals-audit.md:31`. It is a confirmation of the recorded format and arithmetic, not a new panel observation.

`maintenance/hakios-lithium/peripherals/touch-queue.h:6-12,49-55` keeps physical coordinates, render viewport and 0..65535 digitizer normalization distinct. Its 750x1334 example is tested with synthetic endpoints (`maintenance/hakios-lithium/peripherals/touch-queue-test.c:12-15`). UIKit points, framebuffer bytes and physical touch edge calibration remain different quantities; the helpers do not establish correct real orientation, bounds, Dock/labels or physical touch. R16 display sizing itself is marked unverified in `AGENTS.md:1`.

## Morning handoff: factual corrections and unsafe interpretations to flag

No dedicated morning playbook or package entrypoint was inspected, so this is not a complete instruction-safety clearance. Within the scoped evidence, the main task should carry forward these specific flags:

1. **Do not present A2/B2 as implemented, or ask someone to test touch/GPU merely by enabling the new flags.** The design language describes requested stages (`reports/hakios-ios16-lithium-peripherals-audit.md:15`); actual hook behavior is blocked admission (`ports/hakios-lithium/peripherals/kernel.inc:29-36`). `gpu_wd=1` records a request, not a running hardware watchdog. `software_fallback=1` is a diagnostic string, not this review's end-to-end fallback verification.
2. **Qualify the R16 runtime statement.** `reports/hakios-ios16-lithium-peripherals-audit.md:58` says both R15/R16 measured the CPU contract and that R18 parameters match. R15's affinity observation is recorded in `AGENTS.md:3`; however, `OPERATIONS.md:1` records R16 boot-command acceptance with runtime evidence pending, and `project.json:45,52-54,68,79-82` likewise limits runtime verification to R15 / R16 pending. `AGENTS.md:1` and `PLAN.md:1` retain the earlier pre-boot snapshot. These records are not a single consistent current-state account. No R16 console or R18 package was reviewed here, so this final review cannot independently endorse the broader measured-runtime/parameter claim or infer the phone's present state. Command acceptance and package argument readback are not runtime CPU evidence.
3. **Do not turn stored recovery metadata into morning actions.** `project.json:73` says stock recovery must recreate userdata and describes a key sequence. That would conflict with this task's explicit no-device/no-userdata scope and the preserve-data constraints in `AGENTS.md:3`. It is historical metadata, not authorization to recover, reboot, retry, query or reflash. No such action is part of this review.
4. **Do not promote attestations or mock results into MMIO/DMA permission.** Setting `LQT_ALL_VERIFIED`, the probe's verified booleans, `engine_idle` or `irq_drained` without the corresponding platform proof would bypass evidence rather than establish it (`maintenance/hakios-lithium/peripherals/qup-transfer.h:40-55,200-202`; `maintenance/hakios-lithium/peripherals/gpu-probe.h:37-44`; `maintenance/hakios-lithium/peripherals/gpu-submit.h:160-178`). The fixed mock fence address has no mapping (`maintenance/hakios-lithium/peripherals/gpu-submit.h:94-105`). Also, a software deadline cannot interrupt a synchronous stuck callback (`maintenance/hakios-lithium/peripherals/gpu-probe.h:58-59`); the scoped audit specifically warns that a hung bus read is not rescued by loop timeout (`reports/hakios-ios16-lithium-peripherals-audit.md:52`).
5. **Keep conditional future resource work conditional.** The audit's firmware-handling suggestion is explicitly future/if-required and says host prototypes need no firmware (`reports/hakios-ios16-lithium-peripherals-audit.md:54`). Its GIC section distinguishes GPIO125 from the parent GIC line, calls out immediate unmasking, and requires ownership/range/ARE_NS/route checks first (`:60-67`). Neither paragraph is a validated morning execution sequence. This review authorizes no firmware activity, MMIO access, IRQ attachment or device operation.
